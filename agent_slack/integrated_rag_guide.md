# 통합 데이터 RAG 고도화 및 활용 가이드 (Slack, Gmail, Google Drive)

이 문서는 ParaWorks의 AI 비서가 슬랙뿐만 아니라 **Gmail, 구글 드라이브** 등 모든 사내 데이터를 통합적으로 이해하고 답변할 수 있도록 구축된 데이터 구조에 대한 설명서입니다.

---

## 1. 개요: "데이터 소스는 달라도 사용법은 같습니다"

ParaWorks는 다양한 채널(Slack, Gmail, Google Drive)에서 수집된 데이터를 AI 비서가 일관된 방식으로 활용할 수 있도록 **표준화된 메타데이터 태그 시스템**을 갖추고 있습니다.

AI 비서 담당자는 검색 결과로 나오는 데이터가 무엇인지(Source Type)만 확인하면, 그 안에 담긴 작성자, 날짜, 주제 정보를 동일한 방식으로 꺼내서 화면에 보여주거나 답변에 활용할 수 있습니다.

---

## 2. 통합 메타데이터 설계 (표준 구조)

모든 데이터는 벡터 DB에서 검색될 때 아래의 공통 필드를 포함하여 반환됩니다.

| 필드명 | 설명 | 비고 |
| :--- | :--- | :--- |
| `source_type` | 데이터의 출처 | `slack`, `gmail`, `google_drive` |
| `author_name` | 작성자 또는 발신자 | 실명으로 변환된 이름 제공 |
| `timestamp` | 발생/수정 시점 | 답변 시 "언제"인지 알려주는 근거 |
| `category` | 업무 분류 | AI가 분석한 분류 (Project, Operations 등) |
| `topic_tag` | 세부 주제 태그 | 대화나 문서의 핵심 키워드 |
| `importance` | 중요도 | `High`, `Medium`, `Low` |
| `source_url` | 원본 바로가기 | 해당 메시지나 파일로 즉시 이동하는 링크 |

---

## 3. 소스별 데이터 특징 (AI 비서 활용 팁)

AI 비서가 답변을 구성할 때 소스별로 다음과 같은 정보를 추가로 활용할 수 있습니다.

### 📧 Gmail (이메일)
*   **특징**: 공식적인 의사결정이나 외부 협력사와의 소통 내용이 많습니다.
*   **추가 정보**: `subject`(메일 제목) 필드가 제공됩니다.
*   **답변 예시**: "{author_name}님이 보내신 **'{subject}'** 메일에 따르면, ..."

### 📄 Google Drive (문서)
*   **특징**: 기획서, 보고서 등 정제된 고품질 정보가 담겨 있습니다.
*   **추가 정보**: `mime_type`(파일 형식) 필드가 제공됩니다. (PDF, Word, Spreadsheet 등)
*   **답변 예시**: "{author_name}님이 작성하신 **{mime_type} 문서** 내용에 기초하여 말씀드리면, ..."

### 💬 Slack (메시지)
*   **특징**: 실시간 논의와 빠른 피드백, 단발성 결정사항이 많습니다.
*   **추가 정보**: `channel_name`(채널명) 필드가 제공됩니다.
*   **답변 예시**: "**{channel_name}** 채널에서 진행된 대화에 따르면, {author_name}님이 ..."

---

## 4. AI 비서 담당자를 위한 활용 시나리오

### 시나리오 1: 답변 하단 근거(Citation) 표시
AI 비서가 답변을 마친 후, 소스별 아이콘과 함께 출처를 표시하여 답변의 신뢰도를 확보하세요.

> **AI 비서**: "현재 파악된 RAG 고도화 프로젝트의 마감 기한은 5월 20일입니다."
> * [근거1: 💬 #pjt-ai-memory, 김철수, 2024-05-13]
> * [근거2: 📧 [RE] 일정 확인 건, 이영희, 2024-05-12]

### 시나리오 2: 출처별 필터링 검색
사용자가 질문 시 "메일에서만 찾아줘" 또는 "최근 드라이브 문서 위주로 알려줘"라고 요청할 경우, `source_type` 필드를 활용해 검색 범위를 제한할 수 있습니다.

---

## 5. 데이터 보안 및 승인 정책

모든 소스의 데이터는 아래의 단계를 거쳐 안전하게 제공됩니다.

1.  **AI 분석**: 각 에이전트(Slack Agent, Mail Agent 등)가 데이터를 읽고 자동으로 태그를 답니다.
2.  **사람의 검토**: 관리자가 **Review 페이지**에서 승인(Approve)한 데이터만 벡터 DB에 저장됩니다.
3.  **권한 제어**: AI 비서 담당자는 검색 결과의 `permission_level`을 반드시 체크하여, 질문한 사용자가 볼 수 있는 데이터(`public`, `internal` 등)만 답변에 사용해야 합니다.

---

## 6. 개발자용 데이터 예시 (JSON)

AI 비서가 벡터 검색 엔진에서 받게 될 실제 데이터 구조 예시입니다.

```json
{
  "text": "벡터 DB를 pgvector로 전환하기로 함",
  "metadata": {
    "source_type": "slack",
    "channel_name": "#tech-infra",
    "author_name": "박기술",
    "timestamp": "2024-05-10T10:00:00Z",
    "category": "Project",
    "topic_tag": "Infra Update",
    "source_url": "https://company.slack.com/archives/..."
  }
}
```

이 표준화된 구조를 활용하여 소스 구분 없이 자유롭고 똑똑하게 답변하는 AI 비서를 구현할 수 있습니다.
