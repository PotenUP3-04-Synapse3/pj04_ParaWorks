## 1. 주요 진행 상황 (Progress)

### 1.1 검토 항목(Review Item) 그룹화 및 UI 개편
*   **성과**: 유사한 검토 항목을 묶어서 볼 수 있도록 백엔드 API(`GET /api/v1/review`)에서 `item_type`과 `title`을 기준으로 데이터를 그룹화하여 반환(`groups` 필드 추가)하도록 개편함.
*   **프론트엔드 연동**: 대시보드 검토 페이지(`frontend/src/app/review/page.tsx`)를 아코디언(Accordion) 스타일로 변경하여 여러 에이전트가 중복 생성한 후보를 한눈에 효율적으로 파악할 수 있도록 개선함.

### 1.2 근거 보기(Source Evidence) 작성자 표시 추가
*   **성과**: 검토 시 제공되는 원문 스니펫(Snippet) 본문 텍스트 앞에 발언자(Author)의 이름을 굵은 뱃지 형태로 추가함 (`SourceEvidenceDrawer.tsx` 수정).
*   **가치**: 대화 맥락과 핵심 발언을 누가 했는지 시각적으로 즉각 파악 가능해짐.

### 1.3 하드코딩 룰(Rule-based) 추출기 제거 및 순수 AI 작동 환경 구축
*   **성과**: 기존 데이터 수집 단계(`ingestion/service.py`)에서 데모 목적으로 작동하던 하드코딩 영어 템플릿 로직('Verify evidence...', 'Use Redis...')을 완전히 제거함.
*   **가치**: 시스템이 슬랙 에이전트를 통한 순수 LLM 추론에 의존하게 되어 제품의 본질적인 AI 가치가 확보됨. 기존 생성된 더미 검토 항목은 DB에서 일괄 삭제함.

### 1.4 데이터베이스 스키마 명세서 작성
*   **성과**: `docs/db_schema_specification.md` 문서를 신규 작성하여 사용자 인증, 서비스 통합, 데이터 소스, 지식 베이스 등을 포함한 20개의 핵심 테이블 구조를 문서화함. (PostgreSQL 내장 스키마에 대한 설명 포함)

## 2. 시행착오 및 실수 기록 (Lessons Learned)

### 2.1 LLM 출력 형식을 위한 프롬프트 통제(Normalization) 부족
*   **이슈**: 에이전트가 `item_type`을 대소문자 혼용(`Todo`, `todo`, `Record`)하여 생성하거나, 원문 근거 배열(`source_snippets`)을 빈 배열(`[]`)로 반환하여 프론트엔드에 근거가 미노출되는 버그 발생.
*   **해결**: `agent_slack/agent_slack.py`의 LLM 프롬프트와 Pydantic Field 설명을 강화하여 소문자 규격(`todo`, `decision_record`, `history_event`) 강제화 및 스니펫 누락을 원천 차단함.

### 2.2 로컬 개발 환경 프로세스 관리 (Port Clash) 오류
*   **이슈**: 백엔드 수정 후 서버 재시작 과정에서 기존 `uvicorn` 프로세스가 `8000`번 포트를 점유한 채비정상 종료되어 DB 모듈(`psycopg2`) 로딩 실패에 따른 `500 Internal Server Error` 유발.
*   **교훈**: 서버 재구동 시 윈도우 환경에 남아있는 잔여 데몬 프로세스를 완벽하게 킬(Kill)하고 도커 컨테이너를 스크립트(`paraworks-docker.ps1`)로 통제해야 환경 오염을 막을 수 있음을 재확인함.

### 2.3 링크와 스니펫 배열 길이 불일치 예외 처리
*   **이슈**: AI가 원문 링크 3개에 스니펫을 1개만 추출했을 때, 남은 인덱스에 대해 빈 문자열이 반환되어 화면상 '근거 없음'으로 노출됨.
*   **해결**: 백엔드 응답 생성 로직(`_source_evidence_response`)에서 스니펫 개수가 부족하더라도 마지막 스니펫 텍스트를 재사용하거나 기본 안내 문구를 넣도록 안전망(Fallback)을 추가함.
