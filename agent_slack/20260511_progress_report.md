# [2026-05-11] 슬랙 에이전트 고도화 및 연동 진행 보고서

본 문서는 오늘 진행된 슬랙 지능형 에이전트의 기술적 고도화 내용과 발생했던 문제점, 그리고 향후 연동 계획을 기록합니다.

## 1. 주요 진행 상황 (Progress)

### 1.1 슬랙 데이터 수집 범위 정상화
*   **문제**: 공개/비공개 채널 외에 1:1 개인 DM 및 그룹 DM의 데이터가 수집되지 않음.
*   **원인**: Slack API 응답 객체에서 DM은 `is_member` 속성 대신 `is_im` 또는 `is_mpim` 속성을 사용하는데, 기존 코드에서 이를 누락함.
*   **해결**: `backend/app/connectors/slack.py`의 필터링 로직을 수정하여 모든 대화 타입(Channel, IM, MPIM)을 포함하도록 개선.

### 1.2 지식 추출 구조 고도화 (Taxonomy 도입)
*   **기능**: 단순 텍스트 요약을 넘어 기업 환경에 적합한 4대 업무 분류 체계를 도입.
    - **Project**: 목표와 기한이 있는 프로젝트성 업무
    - **Operations**: 상시 운영 및 유지보수
    - **Administration**: 공통 지원 및 인사/재무
    - **Ad-hoc**: 일회성 이슈 및 장애 대응
*   **기술**: LangChain 1.0의 `with_structured_output`과 Pydantic 모델을 결합하여 LLM이 3차원 JSON 메타데이터를 정확히 반환하도록 구현.

### 1.3 대시보드 연동을 위한 실행 데이터(Todo) 강화
*   **기능**: 할 일(Todo) 추출 시 **담당자(Assignee)**와 **마감 기한(Due Date)** 정보를 추가로 파악.
*   **가치**: 대시보드에서 "누가 언제까지 무엇을 해야 하는지" 시각화할 수 있는 기반 마련.

## 2. 시행착오 및 실수 기록 (Lessons Learned)

### 2.1 API 명세 이해의 부족
*   **실수**: Slack API의 `conversations.list` 응답이 채널 타입에 따라 속성값이 다르다는 점을 간과하여 DM 데이터 누락 발생.
*   **교훈**: 외부 라이브러리나 API 연동 시, 문서상의 예외 케이스와 객체 구조를 더 꼼꼼히 사전 분석해야 함.

### 2.2 도구(Tool) 활용의 비효율
*   **실수**: `replace` 도구 사용 시 원본 코드의 공백이나 특수문자를 정확히 맞추지 못해 여러 번 실패함.
*   **교훈**: 코드 수정 전 반드시 `read_file`을 통해 정확한 현재 상태를 복사하여 사용하고, 작은 단위의 수정을 지향해야 함.

### 2.3 임시 코드와 메인 코드의 혼재
*   **실수**: 테스트용 프론트엔드와 백엔드 코드를 메인 소스 폴더에 직접 작성하여 프로젝트 구조가 일시적으로 지저분해짐.
*   **교훈**: 프로토타이핑 시에는 별도의 `temp` 폴더나 격리된 환경에서 먼저 검증한 뒤 통합(Merge)하는 프로세스를 철저히 준수해야 함.
