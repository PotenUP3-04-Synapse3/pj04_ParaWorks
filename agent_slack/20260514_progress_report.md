## 1. 주요 진행 상황 (Progress)

### 1.1 지식 데이터 DB 스키마 보강 및 Alembic 적용 (Phase 1)
*   **성과**: `DecisionRecord`, `Todo`, `HistoryEvent`, `TimelineEvent` 등 핵심 지식 모델에 `project_key` 컬럼을 성공적으로 추가함.
*   **가치**: 데이터가 생성되는 시점부터 특정 프로젝트 소속임을 증명할 수 있는 고유 꼬리표를 달아, 향후 검색 및 필터링 시 정확도를 보장함.

### 1.2 AI 프로젝트 자동 분류 및 리뷰 수정 로직 개선 (Phase 2)
*   **성과**: Slack Agent가 대화 내용을 분석하여 `topic_tag`를 바탕으로 기존 프로젝트에 매핑하거나 새로운 프로젝트 키(`project_key`)를 자동 생성하는 로직(`_determine_project_from_tag`)을 구현함.
*   **API 개선**: 검토(Review) 화면에서 사용자가 프로젝트를 수동 변경할 때 기존 데이터(중요도, 카테고리 등)가 유실되지 않도록 `PATCH` API에 딥 병합(Deep Merge) 로직을 추가함.

### 1.3 검토 승인 ➔ 타임라인 승격 자동화 (Phase 3)
*   **성과**: 검토 페이지에서 '승인(Approve)' 클릭 시, `ReviewItem`에 담긴 프로젝트 정보가 실제 타임라인 테이블(지식 모델)로 유실 없이 전달(승격)되는 파이프라인을 완성함.

### 1.4 하드코딩 제거 및 동적 대시보드 표출 (Phase 4 & 긴급 픽스)
*   **성과**: 백엔드 코드에 하드코딩된 프로젝트 목록을 제거하고, DB에 실제 데이터가 존재하는 프로젝트들만 동적으로 추출하여 화면 탭(Tab)으로 구성하도록 로직(`list_projects`)을 전면 개편함.
*   **긴급 조치**: 기존 대시보드 API가 구형 데이터(`project_assignment` 타입)만 읽어오는 편식 문제를 해결하여, AI가 새로 생성한 `todo`, `decision_record`, `history_event` 데이터도 타임라인과 프로젝트 탭에 즉시 정상 표출되도록 조치 완료.

### 1.5 통합 데이터 RAG 활용 가이드 구축
*   **성과**: 슬랙, Gmail, 구글 드라이브 데이터를 AI 비서가 일관된 방식으로 처리할 수 있도록 안내하는 통합 가이드(`docs/project-centric-automation-plan.md`)를 작성함.
*   **내용**: RAG 및 DB 스키마 구조를 쉽게 설명하고, 검색 결과에서 필드를 어떻게 UI에 활용해야 하는지와 `Alembic` 스크립트 실행 등 팀원 간 협업 가이드를 제공함.

## 2. 시행착오 및 실수 기록 (Lessons Learned)

### 2.1 도커(Docker) 환경에서의 로컬 DB 포트 충돌
*   **이슈**: Alembic 스크립트 생성 시 기존 `5432` 포트를 점유한 다른 프로젝트(webtoon_postgres)로 인해 ParaWorks DB가 `55432`로 우회 실행되어 인증 오류(FATAL) 발생.
*   **해결**: 일시적으로 `.env` 및 `alembic.ini`의 포트를 컨테이너 실제 포트(`55432`)로 맞추어 스키마 업데이트를 성공시킨 뒤, 다시 `5432` 원본 설정으로 안전하게 복구함. (추후 로컬 포트 관리 주의 요망)

### 2.2 테스트 코드의 레거시 정책 의존성
*   **이슈**: 동적 프로젝트 로직 개편 후, 테스트 코드가 과거 하드코딩된 특정 2개 프로젝트 반환만을 기대하도록 작성되어 있어 실패 발생.
*   **해결**: 테스트 코드가 실제 동적 데이터(예: `project-newbiegenie`)의 반환을 정상적인 성공으로 평가하도록 Assertion 로직을 현대화하여 통과시킴.

### 2.3 타임라인 '투명 인간' 현상 (데이터 유형 편식)
*   **이슈**: 기존 데이터를 클리어하고 다시 동기화하여 승인했음에도 타임라인 화면에 안 나타나는 현상.
*   **해결**: 화면 API가 특정 옛날 데이터 형식만 쿼리하도록 하드코딩되어 있던 것을 발견, 모든 AI 추출 유형(`todo`, `history` 등)을 포함하도록 쿼리 범위를 넓혀 즉시 해결함.
