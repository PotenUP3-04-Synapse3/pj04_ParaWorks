# 프론트엔드 통합 가이드: 슬랙 개인 DM 수집 활성화 (OAuth 방식)

본 문서는 ParaWorks의 슬랙 에이전트가 사용자의 **개인 DM(1:1 대화) 및 그룹 DM(MPIM)** 데이터를 안전하게 수집할 수 있도록 프론트엔드 UI/UX를 구현하기 위한 가이드입니다.

---

## 1. 유저 시나리오 (User Scenarios)

### 시나리오 A: 기본 채널 동기화 (기존)
1. 사용자가 워크스페이스를 연동한다.
2. 봇(Bot Token)이 초대된 공개/비공개 채널의 대화만 수집된다.
3. 개인 DM은 수집되지 않는다는 안내를 확인한다.

### 시나리오 B: 개인 DM 포함 정밀 동기화 (신규)
1. 사용자가 슬랙 설정 페이지에서 **'개인 DM 및 비밀 대화 포함'** 스위치를 활성화한다.
2. 시스템은 "개인 권한 승인이 필요함"을 알리는 팝업을 띄운다.
3. 사용자가 승인 버튼을 누르면 슬랙 OAuth 페이지로 이동하여 **User Scopes**를 승인한다.
4. 연동 완료 후, 사용자의 모든 1:1 대화 내용이 지식 추출 대상에 포함된다.

---

## 2. 추천 UI/UX 설계 (Recommended UI)

### 2.1 슬랙 연동 설정 섹션
- **컴포넌트**: `Switch` 또는 `Checkbox`
- **라벨**: 개인 DM 및 그룹 대화 포함 (High-Precision Sync)
- **설명 문구**: 
    > "활성화 시 봇이 초대되지 않은 1:1 DM과 그룹 메시지에서도 업무 맥락을 추출합니다. 이 기능은 사용자의 개인 권한(User Token)을 사용하며, 데이터는 암호화되어 안전하게 관리됩니다."
- **상태**: 
    - `OFF` (Default): 봇이 속한 채널 데이터만 수집.
    - `ON`: 사용자 권한을 통한 전체 대화 수집.

### 2.2 권한 승인 모달 (Permission Modal)
- 사용자가 스위치를 켰을 때 즉시 OAuth로 리다이렉트하기보다, **신뢰를 주는 단계**를 거치는 것을 추천합니다.
- **포함 내용**:
    - **왜 필요한가?**: "슬랙 보안 정책상 봇은 개인 대화를 볼 수 없으므로, 사용자님의 시야를 공유받아야 합니다."
    - **보안 약속**: "추출된 데이터는 기업 지식 후보로만 사용되며, 원문은 리뷰 완료 후 정책에 따라 마스킹됩니다."
    - **버튼**: [슬랙 권한 승인하기], [나중에 하기]

## 3. 기술 구현 흐름 (Technical Flow)

### 3.1 OAuth Scopes 확장
백엔드에 OAuth 요청을 보낼 때 다음 스코프가 포함되어야 합니다.
- `im:history` (1:1 DM 읽기 권한)
- `mpim:history` (그룹 DM 읽기 권한)
- `users:read` (사용자 이름 매핑용)

### 3.2 API 엔드포인트 규약 (Draft)
프론트엔드에서 백엔드로 연동 상태를 전달할 때 사용할 예시 구조입니다.

**POST** `/api/v1/integrations/slack/user-sync`
```json
{
  "enable_user_token": true,
  "sync_mode": "full_context",
  "callback_url": "https://frontend.url/settings/slack/callback"
}
```

## 4. 보안 및 신뢰성 가이드 (Trust & Security)

사용자가 자신의 개인 대화를 AI에게 넘기는 것에 거부감을 느끼지 않도록 UI에 다음 장치를 마련해 주세요.

1.  **데이터 가시성**: "현재 사용자님의 권한으로 수집된 메시지는 총 X건입니다"와 같은 상태 표시.
2.  **쉬운 해지**: 언제든지 개인 권한을 철회(Disconnect User Token)할 수 있는 버튼 제공.
3.  **검토 단계 강조**: "추출된 모든 지식은 사용자님이 직접 검토하기 전까지는 절대 공용 지식으로 등록되지 않습니다." 문구 강조.
