# ParaWorks 배포 런북 (Deployment Runbook)

안정적인 서비스 업데이트와 장애 발생 시 빠른 복구를 위한 배포 절차 가이드입니다.

## 1. 배포 전 체크리스트
- [ ] **DB 마이그레이션 확인**: `alembic upgrade head`가 필요한지 확인합니다.
- [ ] **환경변수 점검**: 새로운 기능에 필요한 `.env` 변수가 설정되었는지 확인합니다.
- [ ] **빌드 테스트**: 로컬 또는 CI 환경에서 모든 유닛 테스트가 통과했는지 확인합니다.
- [ ] **CDN 캐시 퍼지 계획**: 프론트엔드 변경사항이 즉시 반영되어야 하는지 검토합니다.

## 2. 배포 절차

### Step 1. 이미지 빌드 및 푸시
```bash
# Backend 빌드
docker build -t gcr.io/paraworks/backend:latest ./backend
docker push gcr.io/paraworks/backend:latest

# Frontend 빌드
docker build -t gcr.io/paraworks/frontend:latest ./frontend
docker push gcr.io/paraworks/frontend:latest
```

### Step 2. 서버 적용 (Blue-Green Deployment)
- 기존(Blue) 환경을 유지한 채 새로운(Green) 환경을 먼저 띄웁니다.
- `docker-compose -f docker-compose.prod.yml up -d` (Green 환경 가동)

### Step 3. 헬스체크 및 전환
- 새로운 환경의 상태를 확인합니다.
- `curl -X GET http://green-env-url/api/v1/health`
- 정상 응답 시 Nginx/Load Balancer 설정을 Green으로 전환합니다.

## 3. 롤백 절차
배포 후 심각한 오류(에러율 5% 초과 또는 핵심 기능 마비) 발견 시 5분 내에 실행합니다.
1. Load Balancer 설정을 이전(Blue) 환경으로 즉시 복구합니다.
2. `docker-compose up -d` 를 통해 이전 안정 버전 이미지를 다시 가동합니다.
3. Slack `#deploy-alerts` 채널에 롤백 사실과 원인을 공유합니다.

## 4. 배포 후 확인 사항
- Slack `#deploy-alerts`에 배포 완료 알림이 왔는지 확인합니다.
- Grafana/Datadog 대시보드에서 에러 로그 및 Latency 변화를 모니터링합니다.
