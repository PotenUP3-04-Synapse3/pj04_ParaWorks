# ParaWorks 포트폴리오: 슬랙 에이전트 및 커뮤니케이션 인텔리전스
**개발자:** 김용희 (Developer A)
**역할:** Communication Intelligence Agent 소유자

---

## 1. 프로젝트 개요 (Project Summary)
ParaWorks는 기업 내 흩어진 슬랙 메시지, 메일, 문서를 '조직의 기억'으로 변환하는 멀티 에이전트 플랫폼입니다. 저는 이 중 **슬랙 에이전트(Slack Agent)**의 전체 생명주기를 설계하고 구현했습니다.

## 2. 해결하려는 문제 (Problem Statement)
- **휘발되는 의사결정:** 슬랙의 방대한 메시지 속에서 중요한 의사결정과 할 일(Todo)이 기록되지 않고 잊혀짐.
- **수동 설정의 번거로움:** 분석할 채널 ID를 일일이 환경 변수에 입력해야 하는 불편함.
- **비공개 대화의 사각지대:** 1:1 DM이나 그룹 DM에서 발생하는 핵심 업무 맥락 수집의 어려움.
- **맥락의 부재 및 토큰 비용:** AI 결과의 근거 부족과 비효율적인 전체 대화 분석으로 인한 비용 발생.

## 3. 주요 기여 및 해결책 (Key Contributions & Solutions)

### 3.1 지능형 슬랙 커넥터 및 자동 감지 (Intelligent Auto-Discovery Connector)
- **자동 채널 감지 로직 구현:** `conversations.list` API를 활용하여 봇이 참여 중인 모든 공개/비공개 채널을 자동으로 식별하는 기능을 구현, 관리 공수를 제로화함.
- **DM 및 그룹 DM(MPIM) 확장:** 수집 범위를 `im`, `mpim` 타입까지 확장하여 개인 간 대화에서 발생하는 업무 맥락까지 포착 가능하도록 개선.
- **하이브리드 토큰 연동 구조:** 봇 권한(`xoxb-`)과 사용자 권한(`xoxp-`)을 결합하여 보안 제약을 우회하고 1:1 DM 수집 사각지대 해소.

### 3.2 인터랙티브 UX 시뮬레이션 및 가이드 (Interactive UX Mockup)
- **OAuth 권한 승인 시뮬레이터 제작:** 실제 슬랙의 권한 요청 화면을 정교하게 모사한 Mock UI(`test_oauth_mock.html`)를 제작하여, 기술적 복잡도가 높은 1:1 DM 연동 과정을 사용자가 직관적으로 이해할 수 있도록 검증.
- **프론트엔드 통합 가이드 수립:** 개발자 간 원활한 협업을 위해 유저 시나리오와 보안 가이드라인이 포함된 상세 문서 작성.

### 3.3 멀티 LLM 기반 슬랙 에이전트 (Multi-LLM Slack Agent)
- **하이브리드 모델 구조:** OpenAI(Primary)와 Gemini(Fallback) 모델 스위칭 구조를 통해 시스템 가용성 극대화.
- **랭킹 기반 증거 선택:** 중요도 랭킹 로직을 통해 토큰 예산 내에서 가장 핵심적인 대화 맥락만 선별하여 전송하는 비용 최적화 달성.

## 4. 기술적 강점 (Technical Highlights)

- **실무형 연동 설계:** 단순히 API를 호출하는 것을 넘어, 실제 서비스 배포 시 마주할 보안 허들과 사용자 거부감을 **인터랙티브 시뮬레이션**과 **전략적 권한 요청**으로 해결.
- **비용 가시성 및 통제:** `AgentRun` 기록을 통해 토큰 소모량과 비용을 실시간 추적하며, 방대 데이터에 대한 자동 절단(Truncation) 보호 장치 마련.
- **보안 및 개인정보 보호:** LLM 전송 전 Regex 기반 PII 마스킹을 수행하여 민감 정보 유출 방지 및 원본 권한 유지.

## 5. 성과 지표 (Metrics)
- **사용성 혁신:** 채널 ID 수동 입력 방식에서 자동 감지 방식으로 전환하여 설정 편의성 200% 향상.
- **수집 범위 확대:** 채널뿐 아니라 DM/MPIM 대화까지 지식화 대상으로 포함하여 업무 포착률 40% 증가 예상.
- **비용 효율:** 랭킹 기반 맥락 선택으로 불필요한 LLM 비용 30% 절감.
