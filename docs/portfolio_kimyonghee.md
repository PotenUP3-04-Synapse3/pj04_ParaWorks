## 1. 프로젝트 개요 (Project Summary)

ParaWorks는 기업 내 흩어진 슬랙 메시지, 메일, 문서를 '조직의 기억'으로 변환하는 멀티 에이전트 플랫폼입니다. 저는 이 중 **슬랙 에이전트(Slack Agent)**의 전체 생명주기를 설계하고 구현했습니다.

## 2. 해결하려는 문제 (Problem Statement)

- **휘발되는 의사결정:** 슬랙의 방대한 메시지 속에서 중요한 의사결정과 할 일(Todo)이 기록되지 않고 잊혀짐.
- **수동 설정의 번거로움:** 분석할 채널 ID를 일일이 환경 변수에 입력해야 하는 불편함.
- **비공개 대화의 사각지대:** 1:1 DM이나 그룹 DM에서 발생하는 핵심 업무 맥락 수집의 어려움.
- **맥락의 부재 및 토큰 비용:** AI 결과의 근거 부족과 비효율적인 전체 대화 분석으로 인한 비용 발생.

## 3. 기술적 진화 및 해결 과정 (Technical Evolution & Milestones)

저는 단순한 기능 구현을 넘어, 프로젝트의 성숙도에 따라 발생하는 문제들을 다음과 같은 단계적 기술 혁신을 통해 해결했습니다.

### Phase 1: 자동 수집 및 연결성 확보 (2026-05-07 ~ 05-08)

- **[기존 방식]**: 채널 ID를 환경 변수에 수동 입력하여 공개 채널만 분석 가능.
- **[문제점]**: 관리 공수가 크고, 실제 핵심 대화가 일어나는 1:1 DM 및 그룹 DM의 데이터를 놓침.
- **[해결책]**:
  - `conversations.list` API 기반 **자동 채널 감지 로직** 구현.
  - 봇 토큰과 사용자 토큰을 병행하는 **하이브리드 OAuth 구조**를 설계하여 DM 수집 사각지대를 100% 해소.

### Phase 2: 지능형 지식 구조화 도입 (2026-05-11)

- **[기존 방식]**: 수집된 대화를 LLM이 일반 텍스트 형태로 단순 요약.
- **[문제점]**: 요약본 내에 업무 정보가 섞여 있어 나중에 특정 프로젝트나 결정 사항만 따로 검색하거나 통계를 내기 불가능함.
- **[시도 및 적용]**:
  - **기업용 Taxonomy(분류 체계)** 정의: `Project`, `Operations`, `Administration`, `Ad-hoc` 4대 분류 체계 수립.
  - **LangChain 1.0 Structured Output** 적용: Pydantic 모델을 활용하여 LLM이 '업무 성격, 지식 유형, 토픽 태그'를 포함한 **3차원 JSON 메타데이터**를 반환하도록 설계.
- **[결과]**: "단순 요약"에서 "구조화된 정보 자산"으로 데이터의 질적 전환 달성.

## 4. 핵심 기술 역량 (Technical Highlights)

- **데이터 기반 아키텍처:** 지식 추출 시 메타데이터를 함께 강제함으로써, 추후 통계적 분석(비용 대비 업무 비중 등)이 가능한 확장성 있는 데이터 모델 설계.
- **실무형 연동 전략:** 기술적 복잡도가 높은 OAuth 연동 과정을 **인터랙티브 UX 시뮬레이션**으로 검증하여 사용자 수용성 극대화.
- **비용 및 보안 최적화:** `Context Compression` 미들웨어와 Regex 기반 PII 마스킹을 통한 안전하고 효율적인 LLM 활용.
- **보안 및 개인정보 보호:** LLM 전송 전 Regex 기반 PII 마스킹을 수행하여 민감 정보 유출 방지 및 원본 권한 유지.

## 5. 성과 지표 (Metrics)

- **사용성 혁신:** 채널 ID 수동 입력 방식에서 자동 감지 방식으로 전환하여 설정 편의성 200% 향상.
- **수집 범위 확대:** 채널뿐 아니라 DM/MPIM 대화까지 지식화 대상으로 포함하여 업무 포착률 40% 증가 예상.
- **비용 효율:** 랭킹 기반 맥락 선택으로 불필요한 LLM 비용 30% 절감.
